# 02: Privacy-Scoped Personal Payroll Statement (`My Payroll`) & Staff/Stylist Workspace Navigation

**What to build:** Every authenticated salon employee (`STYLIST`, `STAFF`, `MANAGER`, `ADMIN`) can click **"Lương & Thu nhập của tôi"** directly in the `/pos` workspace header to inspect their own `Personal Payroll Statement` for any chosen period (*Tháng này*, *Tháng trước*, *7 ngày qua*, or custom start/end dates) without exposing other colleagues' base salaries or payouts. The personal payroll view displays the employee's monthly `Base Salary`, accumulated `Commission Ledger` earnings for the period, `Total Payout` ($\text{Base Salary} + \text{Total Commission}$), completed `Orders` and `Service Steps` counts, individual KPI metrics (`Requested Stylist Rate`, `Re-booking Rate`, and average `Service Review` star rating `★`), and an itemized chronological table of every `Commission Ledger` entry earned (showing order code, service name, `Service Step` name, commission formula note, timestamp, and amount). In parallel, staff authentication and workspace navigation are standardized: logging in as `STAFF` or `STYLIST` routes directly to `/pos`, and the `/pos` header navigation displays `/admin` ("Quản trị") only when the authenticated user holds `ADMIN` or `MANAGER` roles while offering safe navigation to the Customer Portal (`/customer/booking`) and user logout controls for `STYLIST` and `STAFF` so employees never hit `/unauthorized` or `403 Forbidden` dead ends.

**Blocked by:** 01: Stylist Quick Service Ticket, Daily Worklog & End-of-Shift Cash/Transfer Handover

**Status:** closed

- [x] A privacy-scoped endpoint (`GET /api/v1/analytics/my-payroll`) accessible to `STYLIST`, `STAFF`, `MANAGER`, and `ADMIN` resolves the authenticated user from the security context and returns only that employee's `Personal Payroll Statement` (`baseSalary`, `totalCommission`, `totalPayout`, `completedOrderCount`, `completedStepCount`, `requestedStylistRate`, `rebookingRate`, `averageRating`, `reviewCount`, and itemized `commissionLedgers`) for the requested `startDate` and `endDate` (defaulting to the current month).
- [x] Branch-wide payroll and P&L endpoints (`GET /api/v1/analytics/staff-payroll`, `GET /api/v1/analytics/pnl`, and `PATCH /api/v1/analytics/staff/{staffId}/base-salary`) remain strictly restricted to `ADMIN` and `MANAGER` (`403 Forbidden` for `STYLIST` and `STAFF`), ensuring peer salary confidentiality.
- [x] The `/pos` header provides a **"Lương & Thu nhập của tôi"** button that opens the `Personal Payroll Statement` modal with quick period presets (*Tháng này*, *Tháng trước*, *7 ngày qua*) and custom date pickers, summary compensation cards, personal KPI badges, and an itemized `Commission Ledger` table.
- [x] Logging in as either `STYLIST` or `STAFF` redirects to `/pos` by default (unless a valid `from` route was requested), and the `/pos` header replaces the unconditional back-to-admin link with role-aware navigation (showing `/admin` only for `ADMIN`/`MANAGER` and providing `/customer/booking` + user account/logout actions for all staff).
- [x] Automated backend integration tests (`StaffPayrollIntegrationTest`) verify `GET /api/v1/analytics/my-payroll` for `STYLIST` and `STAFF` accounts alongside `403` enforcement on branch-wide payroll endpoints, and all frontend components stay strictly $\le 250$ LOC and pass `vitest run` and `vite build`.
