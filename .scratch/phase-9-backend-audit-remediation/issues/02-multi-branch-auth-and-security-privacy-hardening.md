# 02: Multi-Branch Authorization Guard, Staff Privilege Escalation Prevention & Public PII/Production Hardening

**What to build:** Multi-branch salon operations are strictly isolated by branch role boundaries, staff privilege escalation is blocked, customer personal and financial data is protected from unauthenticated enumeration across HTTP and WebSocket channels, and production error/payment defaults are safe out of the box. Branch employees (`MANAGER`, `STAFF`, `STYLIST`) can only view or mutate POS `Orders`, `Branch Inventory`, `Bookings`, staff records, payroll statements, and P&L analytics belonging to their own assigned `branchId`, receiving `HTTP 403 Forbidden` if they attempt to target another branch, while `ADMIN` users retain cross-branch access. When creating or updating staff accounts, `MANAGER` users are blocked from assigning `ADMIN` or `MANAGER` roles and cannot create or modify accounts outside their own branch. Querying the staff directory filters active staff directly in the database rather than loading all users (and `Provisional Customers`) into memory. Unhandled server exceptions are logged with full stack traces on the server while returning a generic `UNCATEGORIZED_EXCEPTION` message to clients instead of leaking internal SQL/JPA error strings. The PayOS sandbox simulation webhook defaults to disabled (`false`) when the configuration property is omitted. Unauthenticated calls to the `Membership Tier` loyalty preview return a masked customer name and omit raw `Cumulative Spend` totals, unauthenticated phone-based `Booking` lookups require a matching `bookingCode`, and STOMP WebSocket subscriptions to branch booking and dispatch topics validate JWT authentication.

**Blocked by:** None (can start immediately)

**Status:** ready-for-human

- [x] A centralized branch-scope authorization guard enforces that non-`ADMIN` authenticated users (`MANAGER`, `STAFF`, `STYLIST`) can only read or mutate resources (`Orders`, `Branch Inventory`, `Bookings`, staff users, and analytics reports) matching their assigned `branchId`, returning `HTTP 403 Forbidden` on cross-branch requests while allowing `ADMIN` full access across all branches.
- [x] Branch `MANAGER` users attempting to create or update a user with the `ADMIN` (or `MANAGER`) role, or attempting to assign a staff member to a different `branchId`, are rejected with `HTTP 403 Forbidden`.
- [x] Listing branch staff queries only active staff records from the database (via indexed branch staff queries) instead of loading the entire user table into memory, ensuring `CUSTOMER` / `Provisional Customer` accounts are never returned in the staff management list.
- [x] The global fallback exception handler logs the full exception stack trace at `ERROR` level and returns the standardized `UNCATEGORIZED_EXCEPTION` message on `HTTP 500` responses without exposing raw database or internal exception messages to the client.
- [x] The PayOS sandbox simulation setting defaults to `false` in application code when the configuration property is not explicitly set, ensuring the unauthenticated simulation endpoint is closed by default in production environments.
- [x] Unauthenticated requests to the customer loyalty preview endpoint return a masked customer name and hide raw lifetime spend figures while preserving tier discount preview functionality, and unauthenticated requests to the phone booking lookup endpoint require a matching `bookingCode` (whereas authenticated staff or the matching authenticated customer can still query by phone).
- [x] STOMP WebSocket client connections/subscriptions to branch dispatch and booking topics validate JWT authentication when an authorization header is required, and automated security/integration tests verify cross-branch `403` enforcement, privilege-escalation blocking, safe `500` error envelopes, and public PII protection.
