# 03: Settlement-Date (`settledAt`) Financial Alignment, Pro-Rated Tier-2 P&L Base Salary & Batch Query (`N+1`) Optimization

**What to build:** Salon managers and stylists get accurate daily and multi-day financial reports—even when carry-over orders are checked in on one day and settled the next—and high-traffic booking calendar and P&L endpoints execute in a small constant number of batch database and Redis queries rather than hundreds of queries inside nested loops. All `PAID` `Order` queries powering the P&L Analytics dashboard, `BOM Wastage` calculations, daily revenue trends, and the `Stylist Daily Worklog` shift handover filter and bucket orders by their settlement timestamp (`COALESCE(settledAt, createdAt)`) rather than creation timestamp, ensuring revenue, cash handover, `Chemical COGS`, and `Commission Ledger` entries all align on the day payment was collected. Tier-2 P&L (Net Profit After Fixed Payroll) pro-rates active staff monthly `Base Salary` by the number of days in the selected reporting period ($\text{Monthly Base Salary} \times \frac{\text{daysInPeriod}}{30}$) so a 1-day or 7-day report deducts the corresponding daily/weekly payroll share instead of a full 30-day month. Calculating available 30-minute `Slots` loads the day's active branch `Bookings` in a single SQL query, checks all candidate Redis `Slot Lock` keys in a single batch `multiGet` call, and aggregates stylist `Service Review` ratings in a single grouped query—eliminating the `240+` SQL and Redis loop calls per page load. Similarly, generating a P&L report batch-loads `Inventory Transactions`, `Commission Ledgers`, and order items across all `Order` IDs in the period in batch queries rather than firing per-order queries inside a loop.
