# 04: Atomic Redis Lua Slot Lock TTL & Lean Codebase/Build Cleanup

**What to build:** Redis 5-minute `Slot Locks` acquire keys and assign expiration TTLs atomically so a transient network drop or crash can never leave a stylist's schedule permanently locked, PDF report generation reuses cached TrueType fonts from memory without re-reading disk files on every export, and unused build dependencies, dead repository interfaces/methods, and legacy duplicate stock fields on `Master Product` are removed. Locking multiple 30-minute `Slot` buckets executes a single atomic Redis Lua script that verifies none of the target keys exist (or heals any key stuck without a TTL) and sets all keys with their 5-minute TTL in one step. The unused blocking `KEYS`-based refresh token revocation method is removed. PDF export loads and caches the Vietnamese Roboto Regular and Bold font byte arrays once in memory at startup (with a clean Helvetica fallback if absent). Finally, the unused `mapstruct` dependency and annotation processor are removed from the Maven build, the three unreferenced repository interfaces and dead repository/lock methods are deleted, and the three legacy stock fields on the `Master Product` entity (`branchId`, `currentStockUnits`, `currentVolume`) are removed so `Branch Inventory` remains the unambiguous source of stock truth.

**Blocked by:** 01: Unified POS Order Settlement, Pessimistic Concurrency Locking & Settlement-Time Retained Deposit Accounting, 02: Multi-Branch Authorization Guard, Staff Privilege Escalation Prevention & Public PII/Production Hardening, 03: Settlement-Date (`settledAt`) Financial Alignment, Pro-Rated Tier-2 P&L Base Salary & Batch Query (`N+1`) Optimization
